# 团队接入

## 一次性接入

先调查目标仓库，再填写 [team-contract.md](../assets/templates/team-contract.md)。接入意味着把现有事实与团队决定写清楚；安装 Skill 本身不代表团队已采纳模板里的任何政策。

1. 找到项目规则真源、需求真源、Git/PR 习惯、测试入口、交付环境和已有批准方式。核对命令是否真的存在；耗时或会影响外部系统的命令按当前授权执行。
2. 把已确认的事实写入团队契约。尚未确定的负责人、命令、环境或阈值写“未确定”，只阻塞依赖它们的步骤。
3. 提供契约的可审查差异。使用已有授权；若会改变项目既定审批、接口或工作流状态规则，按项目要求取得批准后再接入。
4. 将 Skill 目录加入选定的团队仓库并纳入评审。指定维护责任人和版本，避免每个人持有不同正文。
5. 将 [AGENTS 片段](../assets/templates/AGENTS.fragment.md) 合并到项目的 canonical 规则入口；不要覆盖原文件。只有已授权接入时才做这一步。已有 `CLAUDE.md` 兼容入口继续引用 canonical 文件，避免两份规则正文漂移。
6. 用一个范围小、可验证的真实工作项试跑：检查是否正确选择深度，交接者是否能只凭产物继续，以及实际验证证据是否足够。先获得这类证据，再考虑自动触发。

对于有持久队列、提案和 Worker 的知识仓库，读取其项目契约；Skill 不绕过该仓库的正式写入流程。团队开发规范文件与知识源文件也不应混为一类。

## 分发与使用

交付包内 `ai-native-sdlc/` 是完整 Skill。将该目录整体复制到目标项目的 `.agents/skills/ai-native-sdlc/`，使团队使用仓库中同一版本。Codex 的仓库级发现方式见 [官方文档](https://developers.openai.com/codex/skills)。

本机开发安装位置以当前运行环境的 Skill 目录为准；团队分发以仓库中的路径和版本为准，不将作者机器的绝对路径写进项目规范。

Claude Code 团队可按其 [Skills 文档](https://code.claude.com/docs/en/skills) 将同一内容接入 `.claude/skills/ai-native-sdlc/`。本包未测试 Claude Code 的自动发现；其 hooks、工具名和权限配置须依据实际版本配置。不要因目录不同而维护两份各自修改的规范；选择一个真源，另一处通过团队支持的同步方式分发。

`agents/openai.yaml` 是 Skill 的展示元数据，不是常驻协调 Agent，也不会自行启动子 Agent、注册自动化或连接 CI。

Codex 提示词示例：

```text
请使用 $ai-native-sdlc，检查当前仓库并接入团队开发规范。
先交付基于现有事实的团队契约草案与规则差异。
```

```text
请使用 $ai-native-sdlc，实现工单 PROJ-123。
复用工单与现有设计作为真源，按任务规模推进，完成本地验证后交付。
```

```text
请使用 $ai-native-sdlc，只读审查这个 PR 的验收证据，
指出它现在处于哪个交付阶段，以及还缺什么。
```

如果选择器尚未发现新 Skill，可直接指定其 `SKILL.md` 绝对路径要求读取；发现列表更新后再验证显式和隐式调用。文件存在、可读取、被自动发现、实际被调用分别记录。

## 从手工到自动化

| 当前条件 | 可接入的下一步 | 如何验证 |
| --- | --- | --- |
| 目标、命令、验收尚不清楚 | 先补团队契约，用手工交接试跑 | 接收者无需重读聊天就能继续 |
| 意图、规格、计划已能稳定交接 | 由现有工单/PR 事件生成下一阶段候选产物 | 同一事件重复到达不产生重复工作项 |
| 有稳定反馈、Agent eval 与明确权限 | 接入评审和受限 CI 作业 | 分别证明允许、拒绝和失败路径 |
| 有部署证据与已演练回滚 | 按既定运行手册接入指标诊断 | 告警来源、阈值、操作回执和恢复指标均可追踪 |

每项自动化要明确触发事件、产物版本、接收方、允许动作、失败出口和重复事件处理方式。内容发生变化后原批准是否仍有效，由项目契约决定，不凭 Agent 自行延续。

只在用户明确要求相应自动化、且前置条件可验证时实施。外部平台写入和团队消息遵守已有授权；准备接入文档本身不代表要向团队发消息。
